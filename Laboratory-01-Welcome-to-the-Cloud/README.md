# Laboratory 01: Welcome to the Cloud

## Mission Overview

This laboratory activity gave me the opportunity to explore a cloud-based Linux environment through KillerCoda. I practiced working with the Linux terminal and performed basic tasks involving system information, files, and directories.

## Objectives

- Become familiar with a cloud-based Linux environment.
- Practice navigating Linux through the terminal.
- Identify basic information about the Linux system.
- Organize files and directories using Linux commands.
- Practice documenting technical activities using Markdown.
- Use GitHub to organize laboratory work.

## Activities Performed

I started by launching Ubuntu 24.04 through KillerCoda and created a user account named `emimporta`. After logging in, I checked the current username, working directory, and hostname.

I also gathered information about the Linux distribution, kernel version, CPU, total memory, and available disk space. I created Documents, Notes, Reports, and Screenshots directories and created an `about-me.md` file inside the Notes directory. I then organized the laboratory files in my GitHub repository.

## Linux Commands Used

- `sudo useradd` - creates a new Linux user.
- `sudo passwd` - sets a password for a user.
- `su` - switches to another user account.
- `whoami` - displays the current username.
- `pwd` - displays the current working directory.
- `hostname` - displays the system hostname.
- `cat /etc/os-release` - displays Linux distribution information.
- `uname -r` - displays the kernel version.
- `lscpu` - displays CPU information.
- `free -h` - displays memory information.
- `df -h` - displays disk space information.
- `mkdir` - creates directories.
- `cd` - changes the current directory.
- `ls` - displays files and directories.
- `nano` - creates or edits text files.
- `cat` - displays the contents of a file.

## Skills Learned

I learned how to navigate a Linux environment using basic terminal commands. I also learned how to check system information, create and organize files and directories, and use Markdown for documentation. Using GitHub also helped me understand how laboratory work can be stored and organized in a repository.
