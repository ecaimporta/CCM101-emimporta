# Mission Reflection

This laboratory activity helped me understand cloud computing from a more practical point of view. Before comparing AWS, Microsoft Azure, and Google Cloud, I mainly saw them as different companies offering cloud services. After completing the research and client scenarios, I learned that they share many similar services, including virtual machines, storage, networking, identity management, databases, and Kubernetes, but each provider also has strengths that can make it more suitable for certain situations.

Among the three platforms, AWS impressed me the most because of the wide variety of services available for different computing needs. I would choose AWS because I am interested in learning how its services can be used together to build and manage different types of cloud environments.

One important lesson I gained from this activity is that selecting a cloud provider should not be based only on popularity. Business requirements should guide the decision. Existing technologies, workloads, future growth, and the services needed by an organization can affect which provider is the better choice.

Acting as a Cloud Solutions Consultant taught me to examine a client's situation first before recommending a solution. The client scenarios showed me that different organizations can have completely different priorities even when they all need cloud computing. The KillerCoda activity also helped me connect cloud concepts with an actual Linux server environment by examining its operating system, CPU, memory, and disk resources.

My GitHub portfolio has improved because my laboratory work is now organized and documented in one repository. It shows my research, comparisons, recommendations, screenshots, and practical activities, making my progress in learning cloud computing easier to review and follow.
